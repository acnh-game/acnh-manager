# 启动自检页与「安装到桌面主菜单」(1.2.0 计划)

本文件是这两条相邻功能的定稿方案,尚未实施。范围只限本文件描述的两件事:**启动自检页**(把"程序该
在哪一份"修成标准状态)和**安装到桌面主菜单**(让本应用从桌面方块直接启动)。与游戏安装器、清单、
网络来源有关的任何内容都不在这里。

版本:Minor → **1.2.0**。

## 1. 为什么是"前置自检"而不是详情页一行

程序放在哪一份,影响的不是整洁,而是三件功能能不能成立:

1. 桌面方块里存的是**一条固定路径**(标准路径),程序放在别处时方块指向空文件;
2. 方块身份(title id)是"路径 + 参数"的哈希,同一个程序放在两个路径就是两个方块;
3. 应用的自更新只会写标准路径,若这次运行的是别处那一份,更新会写去另一份,而用户看不出来。

所以这件事必须在"用户真正开始用"之前解决:正常环境直接进首页,异常环境在启动页拦住,只给一个动作。

## 2. 启动自检页

### 2.1 位置与生命周期

- 启动顺序:**SD 挂载 → 日志打开 → 自检页 → 首页**。正常环境不出现这一页(零额外操作)。
- 异常时拦截。页面上**只有一个动作按钮**,没有"暂不处理 / 跳过";除按钮外只有 `B`(等于退出应用)。
- 环境变更**下次启动才生效**,所以按钮的语义是「**修复并重启**」:动作做完后调
  `envSetNextLoad(标准路径, 标准路径)` 再正常退出 —— hbmenu 与 hbl 都认这个约定,会把当前进程直接
  换成标准位置那一份。调用失败、或宿主不认这个约定时,显示「**已修复,请自行重启**」。
- 失败(卡满 / 只读 / 删不掉)时**停在同页可原地重试**,并写明原因;"复制已成功、只是删源失败"记一行
  日志后继续,不再阻挡。
- **dev 构建豁免**(现有 `DEV_AIDS` 开关):开发循环里会把 nro 放在别处跑,那种情况不该被搬进标准位置。

### 2.2 判定:只用可验证的事实

- 标准路径 = `/switch/ACNH-Manager/acnh-manager.nro`。
- 运行路径取自 `argv[0]`(hbmenu 与 hbl 都会把 nro 路径传进来)。**拿不到或不像路径 → 只报告,不动手**。
- 标准位置那份"是不是本应用"和"版本是多少":读它的 NRO 头与内嵌 NACP —— 资源头(`ASET`)紧跟在代码段
  之后,`NACP` 位于 `header.size + asset.nacp.offset`;这正是 hbmenu 读 NRO 元数据的同一套读法
  (`nx-hbmenu/common/menu-entry.c`)。比较 `NacpStruct.version`(数值版;为 0 时回退解析
  `display_version`)与自身编译进去的 `ACNH_APP_VERSION`,并用 name/author 认身份。
- 同版本时再比**构建**:比大小与 sha256;不同则以文件 mtime 取新的一方。

### 2.3 动作与文案

动作顺序固定为:**复制 → 校验(大小 + sha256)→ 删源**。不能"先删后复制":一次写卡失败就两头空;
而删源是"搬运"的意义所在,不删就会因为 id 由路径决定而迟早出现两个方块。

| 标准位置那份 | 比较结果 | 页面 | 按钮 | 动作 |
|---|---|---|---|---|
| 不存在 | — | 不出现 | — | 静默搬运(复制→校验→删源)→ 重启到标准版 |
| 是本应用 | 标准那份更高 | 提示 | 「修复并重启」 | 删除当前这份 → 重启到标准版 |
| 是本应用 | 当前更高 | 提示 | 「修复并重启」 | 用当前覆盖标准位置 → 重启到标准版 |
| 是本应用 | 同版本 | 提示 | 「修复并重启」 | 构建相同:删当前并重启;构建不同:按 mtime 取新的一方,仍不询问 |
| 非本应用 / 读不出 NACP | — | 提示 | 「修复并重启」 | 覆盖标准位置 → 重启到标准版 |

文案纪律:

- 用户可见处**不出现"矫正"**这种词,只有"修复 / 重启";
- 覆盖标准位置前**不列**被覆盖文件的细节(用户不关心);
- 一句话说清"现在怎样 + 按下去会发生什么",不解释内部机制。

## 3. 安装到桌面主菜单

### 3.1 方块身份(title id)

照抄参考实现的算法:`0x0500000000000000 | (hash(nro 路径 + 参数) & 0x00FFFFFFFFFFF000)`
(`sphaira/source/owo.cpp:917-920`),本应用固定用**标准路径 + 空参数**。含义:同一路径同一份程序永远
得到同一个 id,无论用户用 sphaira 还是用本应用安装,都只占一个方块;用户先前用 sphaira 从同一路径装过
的那个方块,在本应用眼里就是"已安装"。

### 3.2 forwarder NSP 从哪来(省力路线)

- 由仓库里的一个**离线工具**生成一次(不自研 NCA/CNMT 构造器,也不自研加载器),布局照参考实现:
  exefs = hbmenu 的加载器(`main` + `main.npdm`);romfs = `nextArgv` 与 `nextNroPath`(都写标准路径;
  hbl 两者都读,缺一会拒绝启动);NACP name 各语言都写 `ACNH-Manager`、author `acnh-game`、
  version = 应用版本、图标用 `assets/icon.jpg`;再加 IVFC/PFS0 那一套哈希结构。
- 产物进 `data/`(bin2s 输入,带 `.bin` 后缀),像内嵌 agent payload 一样**记录来源与哈希**,并由发布
  自检核对。
- app 内只做两件事:把这份**内嵌 NSP** 装上去、或把它删掉。
- 许可:内嵌第三方加载器 + 本应用自身保持开源,署名写在 README/关于页(已确认可以)。

### 3.3 首页按钮

- 位置:现有按钮**下面单独一行(全宽)**。
- 标签在两种状态间切换:「安装到桌面主菜单」/「从桌面主菜单移除」;副标题只说会发生什么
  (如"装好后可从桌面直接启动"),不提内部概念。
- 安装目标:**SD**。
- 按下安装前先跑一次路径自检(第 2 节);当前是非标准路径时先走修复流程,避免装出一个指向空文件的方块。

### 3.4 移除

- 删该 title 的内容与记录(现成引擎路径),可能需要回到桌面刷新一次;
- 不碰任何存档(加载器不写存档);
- **不处理**"方块指向别的路径"这种历史遗留 —— 已知取舍:最坏是用户机器上两个方块。

## 4. 日志与详情页

- 日志首行:`launch: mode=application|applet path=… program-id=0x… layout=standard|nonstandard`
  (两种启动方式写在同一个 `log.txt` 里,这一行是分开它们、也是自检结果的落点)。
- 详情页保留一行"程序位置:标准 / 非标准"(自检修好后显示标准)。
- **界面上不出现任何关于签名、补丁、加载器的说明**(实现者背景:自建条目没有任天堂签名,能否启动取决于
  用户自己的系统;这句话只留在本文件里,屏幕上一个字都没有)。
- 上屏文案(按钮标签、副标题、自检页提示与失败文案)全部进 `source/i18n/strings.*`,中英两列都填。

## 5. 实施步骤

1. **启动自检页**:判定 + 上表五格 + 复制/校验/删源 + `envSetNextLoad` 重启 + 失败重试 + dev 豁免 +
   日志首行;主机侧可测的判定逻辑(路径比较、NRO 头/NACP 解析、动作计划生成)单独成纯逻辑模块并由主机
   测试钉住。
2. **桌面方块**:离线生成工具 + 内嵌 NSP + 首页第 4 个按钮(安装 / 移除 / 状态识别)。
3. **文案与文档**:i18n 两列、本文档同步、真机验收记录。

本计划**先不实施**,等指令。

## 6. 验收(真机用例)

| # | 手法 | 期望 |
|---|---|---|
| 1 | 从标准路径启动 | 不出现自检页;日志首行 `layout=standard` |
| 2 | 复制一份到 `/switch/acnh-manager.nro`,从那里启动 | 自检页出现;按「修复并重启」后回到标准位置运行,根目录那份已不存在 |
| 3 | 标准位置放一份更高版本 | 提示 + 删当前 + 重启后跑标准版 |
| 4 | 标准位置放一份更低版本(当前更高) | 覆盖标准位置 + 重启 |
| 5 | 标准位置放同版本同构建 | 静默修复并重启(不询问) |
| 6 | 标准位置放同版本不同构建 | 按 mtime 取新的一方,不询问 |
| 7 | 标准位置放一个非本应用的文件 | 覆盖 + 重启 |
| 8 | 卡只读 / 卡满 | 停在自检页并写明原因;恢复后原地重试成功 |
| 9 | 按「安装到桌面主菜单」 | 桌面出现方块,能从桌面启动;详情页与日志有记录 |
| 10 | 再按一次(已安装状态) | 显示「从桌面主菜单移除」;移除后方块消失,相册入口照常可用 |
| 11 | 先用 sphaira 从同一路径装过方块 | 首页按钮显示"移除"(身份识别正确) |
| 12 | dev 构建放在非标准路径启动 | 不触发自检(豁免生效) |

## 7. 已定稿的取舍

1. **没有跳过**:环境不对就不提供服务,只给"修复并重启"这一个动作 —— 因此判定必须保守(只用能验证的
   事实),动作必须能原地重试。
2. **界面不解释技术原因**:签名、补丁、加载器一律不上屏。
3. **覆盖标准位置前不列细节**:用户不关心被覆盖的是什么。
4. **方块指向旧路径的历史遗留不处理**:最坏是机器上两个方块。
5. **内嵌预生成 NSP**:不自研 NCA/CNMT 构造器,也不自研加载器。
